# 呈现规则（用户逐条确认，勿倒退）

> 这些规则全部来自用户对成片的直接反馈，多条曾被相反做法否决过。
> 换路线、出新版本时默认沿用；要改必须用户明确改口。
> 背后的审美标准：**物理直觉 + 画面干净**——多余元素（人物贴纸、凭空出现的车、被抹掉的 logo）都读作瑕疵。

## 1. Google logo 必须保留，只交付单一 logo 版本

- 合成时 `KEEP_WM=1`（跳过修复，保留 ES 云渲染帧右下角烧录的字标 + 版权行）。
- **不要输出去水印版**，也不要 `_logo` 后缀制造两份文件（v16 双版本并存导致用户拿错文件）。
- 若将来确需无痕去除：正路是**时间域修复**——相机在动，被水印挡住的地面在邻帧可见（±0.4s 位移 >220px > 框宽），用合成器的相机投影把邻帧同一地面 QUAD-warp 回来填充；静止机位时段回退边界插值（静止时补丁不可见）。

## 2. 步行段不画人物精灵

- "人的图标太丑……别画人了，就用一个动态的线从A连到B表示步行就行了。"
- 动态虚线本身就是步行表达：未走 = 黑衬 w6 + 淡蓝 w2 虚线（on=14px / off=10px）；已走 = 辉光 w10 + 白 w4。虚线顶点按 0.1s 采样入 route，随帧逐段翻色，**线的生长端即当前位置**。
- 换乘步行 1–2s 即可（口岸过关 / 机场大厅→跑道 / 停机位→出口）。

## 3. 结尾不追加车辆

- 最后一程的载具抵达后**原地停靠**，画完全景拉远（tail remap：把收尾帧改写为最后一程载具定格在抵达锚点）。
- 载具 = 实际坐过的交通工具，不凭空加、不换车收尾。

## 4. 图标缩放：严格 ∝ 1/相机高度 + 同高度等大

- `scale = min(1.0, max(0.12, 13500/alt))` —— 高度翻倍图标精确减半（15km→135px、30km→68px、45km→45px、80km→25px）。
- 所有底图归一化到**长边 150px**（plane 150×150、car/moto 150×86、boat 150×45）——同高度所有图标等大，同一套尺寸语言。
- 0.12 地板（≈18px）是唯一必要妥协：纯反比在数 Mm 巡航高度会把图标缩成 0.2px 消失。
- **教训**：幂律 `(13500/alt)^0.2`、指数 0.55 等折中方案被否两次——非严格反比在低跨度段读成"屏幕贴纸"；底图按各自宽高比归一化会导致同高度大小不齐。

## 5. 载具预等待与停靠

- **预等待**：第 n 段播放时，第 n+1 段的载具已在其**精确起点锚点**等待（从 t=0 画到自己开跑），杜绝"突然出现"；步行段无载具不参与。
- **停靠**：完成段的载具停在**精确地理锚点**逐帧投影，不避让、不偏移。
- 绘制顺序：等待 → 停靠 → 当前（新遮旧，当前载具最后画）。

## 6. 标签

- 起点不标文字（用户："起点的位置不用标记文字"）；目的地度假村类标签不加（停靠的载具就是目的地标识）。
- 机场标签常显；码头/口岸等换乘点标签带时间窗 + 0.3s 线性淡入出。
- 字体：中文 34px / 英文 20px（msyh.ttc）。
